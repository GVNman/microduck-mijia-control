# 米家语音控制（mihome-voice）

> **这个文件夹是干嘛的：一句话——让鸭子听懂你说的话，帮你开灯、拉窗帘。**
>
> [English version](README.en.md) · [回总览](../README.md)

## 先看一眼：能做什么

| 你对鸭子说 | 鸭子帮你做 |
|---|---|
| 开窗帘 / 打开窗帘 / 拉开窗帘 / 关窗帘 | 客厅窗帘打开 / 合上 |
| 开吊灯 / 打开吊灯 / 关吊灯 / 关闭吊灯 | 吊灯开 / 关 |
| 开柜子灯 / 打开柜子灯 / 关柜子灯 / 关闭柜子灯 | 三盏柜子灯同时开 / 关 |

小提示：前面加“鸭子”“小鸭子”“请”“吧”都行，比如“鸭子，开吊灯”。
说“不要开灯”“别开灯”这种否定句，鸭子听得懂，但不会执行（故意这样设计的）。

## 这个文件夹里每个文件是干嘛的

| 文件 | 作用 | 放到鸭子的哪里 |
|---|---|---|
| `voice_commands_mihome.py` | 核心代码：收到“开吊灯”就去调米家接口，收到“关窗帘”就去关窗帘电机。里面写了三个设备的编号（DID），要改成你家的 | 参考代码，按说明接进鸭子自己的 `voice_commands.py`（不是直接覆盖） |
| `speech_grammar_snippet.md` | 要识别的中文词表：告诉鸭子哪些词是命令。不在词表里的词，鸭子会当成听不懂 | 里面的词加到鸭子 `speech_control.py` 的 `COMMAND_GRAMMAR` 里 |
| `duck-echo-mihome.conf` | 系统配置：鸭子的语音服务默认读不到 `/home` 目录、也连不上网，这个配置给它开权限，不然所有命令都会失败 | `/etc/systemd/system/duck-echo.service.d/mihome.conf` |

## 工作原理（不用懂也能用）

```
你说话 → 鸭子本地识别语音（Vosk，离线，不用联网）
       → 找到对应的命令 → 调用米家接口（mijia-api）
       → 灯 / 窗帘执行动作
```

- **Vosk**：鸭子自带的离线语音识别，声音不用传到云端。
- **mijia-api**：一个开源的米家设备控制库，本项目用它跟家里的设备说话。
  本文件夹不包含它，你需要另外安装（下面第 2 步）。

## 开始之前，你需要

- [ ] 一只 Microduck 机器人（Radxa Zero 3W），官方软件 **2026.11.4 或更新版本**，语音功能（duck-echo）能正常工作。
- [ ] 一台能 SSH 连上鸭子的电脑（装文件、改配置都要用）。
- [ ] 家里有米家设备（窗帘、灯等），已经在米家 App 里配好、能正常控制。

## 详细步骤

### 第 1 步：放系统配置文件

把本文件夹的 `duck-echo-mihome.conf` 复制到鸭子的
`/etc/systemd/system/duck-echo.service.d/mihome.conf`，然后重新加载系统配置：

```bash
sudo systemctl daemon-reload
```

> 为什么要这一步：鸭子的语音服务运行在一个“沙箱”里，默认读不到 `/home` 目录、也连不上网。
> 没有这个配置，它找不到米家库，所有语音命令都会失败（报错 `No module named 'mijiaAPI'`）。

### 第 2 步：安装米家控制库

在鸭子上安装 [mijia-api](https://github.com/Do1e/mijia-api)（二选一）：

```bash
pip install mijiaAPI
```

或者把库复制到 `/home/radxa/mijia-api`。

装好后登录一次，让它生成授权文件（`~/.config/mijia-api/auth.json`）：

```bash
python3 -m mijiaAPI --login
```

> 授权文件只留在鸭子上，**绝对不要**把它传到网上、也不要放进这个仓库。

### 第 3 步：查出你家设备的编号（DID）

每个米家设备都有一个编号，叫 DID。查一下：

```bash
python3 -m mijiaAPI --list
```

记下你要控制的设备编号（窗帘、吊灯、柜子灯）。灯组会显示成 `group.<一串数字>` 的样子。

### 第 4 步：把编号填进代码

打开 `voice_commands_mihome.py`，把你查到的 DID 填到对应的位置
（文件里有注释，标明了哪里填窗帘、哪里填吊灯、哪里填柜子灯）。

然后按文件底部的说明，把处理代码接进鸭子自己的 `voice_commands.py`
（命令分发那两处），再把 `speech_grammar_snippet.md` 里的词加到
`speech_control.py` 的 `COMMAND_GRAMMAR` 里。

> 这一步是必须的：语音识别只认词表里的词，不在词表里的词会被识别成 `[unk]`（听不懂）。

### 第 5 步：重启语音服务，试一句

```bash
sudo systemctl restart duck-echo
```

然后对鸭子说一句“开吊灯”，看灯亮不亮。

## 怎么验证装好了

1. 说“开吊灯”，吊灯亮；说“关吊灯”，吊灯灭。
2. 说“开窗帘”，窗帘打开；说“关窗帘”，窗帘合上。
3. 说“不要开灯”，鸭子不执行（说明否定句识别正常）。

## 常见问题

**Q：说了命令，鸭子没反应？**

A：先查两处：① `COMMAND_GRAMMAR` 里有没有加这个词，没加的词识别出来是 `[unk]`；
② `duck-echo-mihome.conf` 有没有放对位置、放完有没有 `daemon-reload`。
再看日志里有没有 `No module named 'mijiaAPI'`，有就是米家库没装好。

**Q：命令执行了，但 App 里状态没变 / 读设备超时？**

A：有些设备（窗帘电机、Mesh 开关）动作本来就慢，读状态还经常超时，
但写命令其实已经发出去了。以家里的实际设备为准，别只看返回值。

**Q：开关有好几个按键，怎么指定按哪一个？**

A：用编号后面的属性，比如 `on-4` 就是这个开关的第 4 路。按你家的接线改。

**Q：鸭子升级系统之后，语音控制没了？**

A：正常。鸭子升级会覆盖 duck-echo。升级之前先把你改过的
`voice_commands.py`、`speech_control.py` 和本文件夹的文件拷出来备份，
升级完再重新装一遍。

**Q：隐私怎么样？我的声音会传到云端吗？**

A：不会。语音识别在鸭子本地完成。米家控制走的是你自己家局域网和米家账号，
不经过任何第三方语音云。

## 安全提醒

- **这个文件夹里没有任何真实凭据。** 设备编号一律是 `YOUR_*` 占位符。
- 只在你自己的鸭子上填真实信息，填完的配置和授权文件（`auth.json`）**永远不要**提交到公开仓库。
